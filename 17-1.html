JSON 数据格式演示

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式，采用完全独立于语言的文本格式， 是前后端数据传输最常用的载体。下面从语法规则、值类型、与 JS 对象的区别、序列化以及树形结构五个角度演示。

1JSON 的六条语法规则

  • 1数据以键值对形式组织，格式为 "键": 值，键与值之间用冒号分隔。
  • 2键名必须使用双引号包裹，不能使用单引号，也不能省略引号。
  • 3同一层级的键值对之间用英文逗号分隔，最后一个键值对后面不能加逗号。
  • 4对象使用花括号 {}，数组使用方括号 []，可层层嵌套。
  • 5值只能是：字符串、数字、布尔值、null、对象、数组，不能是函数、undefined 或日期对象。
  • 6JSON 是纯数据文本，不含注释，也不能使用变量，整体必须以一个值开始和结束。

2一个标准 JSON 示例

{
"学号": "1012",
"姓名": "陈卓然",
"年龄": 20,
"在读": true,
"专业": {
    "名称": "高级网页设计",
    "学分": 3.5
},
"技能": ["HTML", "CSS", "JavaScript"],
"备注": null
}

上例包含对象嵌套对象（专业）、对象嵌套数组（技能），以及字符串、数字、布尔值和 null 四种基本值。

3常见书写错误

✗ 错误（键没加双引号）
{ 学号: "1012" }

✗ 错误（用了单引号）
{ '姓名': '陈卓然' }

✗ 错误（末尾多了逗号）
{ "年龄": 20, }

✗ 错误（注释不是合法的 JSON）
{ "年龄": 20 /* 二十岁 */ }

✓ 正确
{ "学号": "1012", "年龄": 20 }

2被 JSON 排除的类型

下面这些 JavaScript 中的值不能被 JSON 表示，序列化时会被丢弃或变成 null：

undefined      → 作为对象属性时被丢弃，作为数组元素时变成 null
function       → 整个键值对被丢弃
Symbol         → 键值对被丢弃
NaN / Infinity → 序列化成 null
Date           → 序列化成 ISO 格式字符串（并非原生支持，靠 toJSON 转换）

1JSON 文本 vs JS 对象字面量

两者写法相似，但 JSON 是纯文本数据，JS 对象是内存中的引用数据，区别如下：

✓ 合法的 JSON

{
"name": "陈卓然",
"age": 20,
"tags": ["HTML"]
}

键必须双引号 · 值只有六种类型 · 无逗号结尾 · 无注释

✗ 不是 JSON（是 JS 对象）

const czr_obj = {
    name: '陈卓然',
    age: 20,
    say: function () {},
    tmp: undefined
};

键可省略引号 · 可用单引号 · 可含函数/undefined/变量

2核心区别一览

  • 1本质：JSON 是字符串（文本），JS 对象是内存中的数据结构。
  • 2键名：JSON 必须双引号；JS 对象可省略，也能用单引号或数字。
  • 3值类型：JSON 只允许 6 种；JS 对象还可包含函数、undefined、Symbol、Date、正则等。
  • 4注释：JSON 不允许任何注释；JS 对象可写 // 与 /* */。
  • 5转换：对象 → JSON 用 JSON.stringify()；JSON → 对象用 JSON.parse()。

2JSON.stringify() —— 对象转字符串

把 JavaScript 对象序列化成 JSON 文本，第三个参数可控制缩进空格数。

var czr_obj = { name: "陈卓然", age: 20, skills: ["HTML", "CSS"] };
JSON.stringify(czr_obj);      // 压缩成一行
JSON.stringify(czr_obj, null, 2); // 缩进 2 个空格
